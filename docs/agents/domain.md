# Domain documentation

This is a single-context repository.

Before changing product behavior or terminology, read root `CONTEXT.md`. Read applicable records under `docs/adr/` if that directory exists. Use glossary terms consistently in specs, tickets, code, and tests.

`CONTEXT.md` is a glossary, not an implementation specification. Product behavior belongs in `SPEC.md`; hard-to-reverse, surprising trade-offs may be recorded under `docs/adr/`.
